# mcp — how we build (Go, MCP bridge and direct CLI)

`mcp` is a thin client: with no command it forwards JSON-RPC frames from an MCP client's stdin to `POST /api/mcp/rpc` on the portal and writes correlated responses back to stdout; with a command it exposes that same server-owned tool surface to a shell. Stdio mode owns only transport invariants: bounded framing, request-id correlation, Streamable HTTP headers, response validation, and notification silence. Direct CLI `--json` makes one logical tool invocation, follows no continuations, and prints the server's `structuredContent`; human mode adds bounded, terminal-safe presentation for the thirteen fixed tools and follows only exact server-issued observation continuations after `run_action` or `execute_runbook`. The portal still owns every descriptor, argument contract, content block, policy decision, and continuation. Bridge-attested `run_action` dispatch (`sign.go`) reads the exact execution intent to create an Ed25519 attestation because the signing key must stay in the bridge. Keep that boundary: new tool behavior belongs in the portal, while CLI presentation may adapt only to the fixed published contracts.

**Dynamic action catalogs are server-owned.** Never require operators to mirror
current action ids into client `enabled_tools` / `includeTools` configuration:
runner scope, connectivity, and advertised packs change underneath such lists.
Large-catalog discovery is a portal contract; the bridge remains transport-only.

Read the root `../AGENTS.md` (the creed) first; the Go house style is in `runner/AGENTS.md` and applies here too.

## The gate

Run from the repository root:

```
./run gate mcp
```

It checks client-module boundaries and formatting, module checksums, `go vet`,
`staticcheck`, tidy-as-a-no-op plus the stdlib-only assertion (no `go.sum` may
exist), attestation parity against the runner's copy, race tests, and a
cross-build of every published platform including `windows/amd64` and
`windows/arm64`. CI also runs this gate natively on both Windows architectures
so the PowerShell installer, credential ACLs, and process adapters execute
rather than merely compile. Go has no race runtime for `windows/arm64`, so that
native lane runs the same tests without `-race`; every other supported lane
keeps race detection. Use
`./run test mcp [go-test-args...]` for focused feedback; direct Go commands are
diagnostic, not final verification.

## Shape

- **Small top-level production files plus the in-tree attestation package, stdlib only.** A new *external* dep needs a strong, stated reason.
  - **`main.go`** — shared startup, bounded concurrent stdio and Streamable HTTP transport, response validation, help/version. It may inspect only envelope metadata needed for transport correctness (`id`, notification and cancellation status, `initialize` protocol version, and the modern transport's routing values — `params._meta`'s declared protocol version plus the `params.name`/`params.uri` mirrored into `Mcp-Name`); it must not interpret tools or content. Mirroring is a byte-copy the portal re-validates against the same body, never a claim the bridge invents: a malformed declaration or a value that cannot ride an HTTP field value is left unmirrored (or sentinel-encoded) so the portal answers with its own protocol error.
  - **`cli.go` + `cli_fleet.go` + `cli_actions.go` + `cli_runbooks.go` + `cli_results.go`** — the shell adapter. It fetches `tools/list` for live names, descriptions, annotations, and input-schema documentation; sends the caller's tool name unchanged through `tools/call`; preserves JSON values without numeric coercion; and prints exact `structuredContent` under `--json`. Human mode has bounded, terminal-safe renderers for the thirteen fixed tools; unknown future tools fall back to the generic renderer. `find_actions TEXT` is the one input convenience and encodes the exact `{"query": TEXT}` object. Unsupported schema shapes point to the exact `--json` descriptor instead of guessing.
  - **`cli_follow.go`** — the human mutation observer. Only default-output `run_action` and `execute_runbook` calls enter it; `--json` always stops after the original logical invocation. It prints the original operation ID first, follows exact `wait_for_run`, `outputs_next`, and `runs_next` reads correlated to the same run or execution, and bounds concurrent runner waits at eight. `runs_next` pagination preserves the exact execution filter and adds only the opaque cursor from the prior `recent_runs` page. Ctrl-C cancels observation only. It never issues a second mutation, invents an identity or cursor, or turns annotations into a client-side authorization or confirmation gate. The shared transport may still resend the identical request under the same operation ID during its bounded network or credential recovery.
  - **`rotate.go` + `rotate_lock_*.go` + `rotate_access_*.go`** — client-prepared API-key rotation and its small platform adapters. Credential state is one owner-only file per canonical endpoint origin + bootstrap prefix; every transition is temp-write, file-sync, rename, then directory-sync. Endpoint-unbound state is never reused. Keep generation, persistence, acknowledgement, refresh, and activation ordered so a crash at any boundary leaves the configured/current key or the pending successor recoverable.
  - **`sign.go`** — the bridge-attested-dispatch seam, and the only transport code that reads tool semantics. It keys off `method == "tools/call"` and exact `params.name == "run_action"`, preserves the public frame unchanged, and returns a private `Emisar-Attestation` header over the exact execution intent. Reads and other mutations are never signed merely because they use `tools/call`. Invalid tool input is forwarded for the portal's normal schema error; once a valid action reaches cryptographic signing, failure stops locally rather than silently sending it unsigned.
  - **`internal/attest/`** — the canonical attestation encoding: the exact bytes the MCP bridge signs and the runner verifies. **Duplicated VERBATIM in `runner/`** (separate Go modules, no shared import by design). Keep both implementations and fixed-vector constants identical in the same change; the root gate mechanically compares them.
- A `bridge` struct holds the endpoint, API key, user-agent, HTTP client, private process nonce, negotiated protocol version, optional `signer`, and key-rotation state (`credentialStore`, `pendingKey`). `serve(io.Reader, io.Writer)` owns admission, in-flight ids, and serialized stdout while a fixed maximum of eight HTTP requests may run concurrently; `forwardRequestContext` POSTs with the Bearer token, the admitted request token, and the MCP protocol header — the version negotiated at `initialize` for a legacy client, or the one the frame itself declares for a modern client, which also carries the `Mcp-Method`/`Mcp-Name` routing headers. Sequential JSON-RPC id reuse is legal; only a concurrent collision is rejected. Every admitted `tools/call` carries a token-derived operation ID so future mutation tools remain portal-owned, while read handlers simply ignore it. The stateless portal issues no `Mcp-Session-Id`; the nonce remains private except through derived request tokens and digests. `notifications/cancelled` bypasses ordinary admission and targets one request generation. Untrusted HTTP bodies reach stdout only after status, media type, UTF-8, JSON-RPC shape, and response-id validation.
- **Key rotation:** only portal-compatible `emk-` secrets use local rotation state; OAuth and arbitrary Bearer tokens pass through unchanged. The bridge durably prepares a random successor, sends only its prefix + SHA-256 digest on authenticated requests, and activates it only after the portal acknowledges that exact digest and the promotion is durable. Lost requests/responses retry the same pending key. The portal installs the proposal atomically and idempotently once the key enters its rotation window; first authenticated use of the successor retires its replaced chain. If durable client storage is unavailable, do not propose a successor. Writable processes refresh endpoint-bound state under the cross-process lock. A sandboxed read-only process never trusts a visible peer rename by itself: it retries a validated current or pending successor only after `401`, with the identical request token and operation identity. Cancellation uses the current credential, and the portal authorizes a successor against only its immediate predecessor's request topic, so a peer promotion cannot strand an in-flight wait.
- **Security:** refuse cleartext `http://` to a non-loopback host (mirrors the runner's `cloud.allow_insecure`). The private process nonce is random and namespaces operations and cancellation generations without masquerading as an MCP session. The signing key and the persisted successor key are secrets that stay in the bridge. The portal validates the bounded attestation envelope and exact target-set match before relaying it, but only the runner is the cryptographic authority.
- It's small enough that **stderr startup diagnostics are right — don't add `slog` ceremony.** A network failure becomes a synthetic JSON-RPC error response, never a closed pipe. Wrap errors with `fmt.Errorf("…: %w", err)`; tests are stdlib + table-driven.
