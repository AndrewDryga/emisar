# Docs provenance stays quiet and actionable

Documentation review dates are provenance, not conversion copy or primary navigation. Render them once in the shared docs chrome, close to the article boundary, with quiet but readable styling that does not compete with the guide or its next-step navigation.

Only offer a contribution or editing action when its destination can complete the action as described. A repository edit URL is not a useful docs affordance when repository policy prevents the reader from committing the proposed change; remove the action and the data passed solely to assemble it.

Runtime evidence is stronger provenance than editorial freshness. When durable
evidence exists, show one short, positive, dated test sentence in the shared
colophon and omit the review date. Otherwise show only the review date. Keep
internal test scope and negative qualification disclaimers in retained
engineering evidence, not customer-facing docs.
