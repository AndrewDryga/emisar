# Docs navigation separates concepts and walkthroughs

When one documentation group contains both generic mechanism or protocol pages and vendor-specific setup walkthroughs, render them as labeled sibling sections rather than one flat list. Put the generic concepts first so readers can understand the contract before choosing a provider guide.

These labels are navigation wayfinding only. They do not create routes or another breadcrumb level, and splitting a section must preserve the established page order unless the task explicitly changes it.

Pin both the section labels and their page membership in the shared navigation tests so a later page addition cannot silently mix concepts and integrations again.
